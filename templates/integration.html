How this talks to the job order system and SAP

Nothing here is connected for real. This page shows where the seams are, so a later integration is a matter of filling them in, not redesigning.

The flow

Job order system
owns the parent build
today: data/job_orders.json
→ job orders + bill of SFGs
file import (later: API pull or webhook)
← SFG status per job order
GET /api/job-orders/<no>/sfg-status
SFG Transfer Tracker
owns inter-plant movements
send · receive · discrepancies · append-only trail
→ goods movements 303 / 305
CSV today (later: SAP API via middleware)
← material document numbers
stored on the transfer (sap_doc_out, sap_doc_in)
SAP
inventory and valuation
plant, material, batch, stock in transfer

Endpoints available now

GET /api/transfersAll transfers with lines and discrepancies. Filters: status, job_order_no, from_plant, to_plant.
POST /api/transfersLog a send (same rules as the form). For a scanner app or another system.
POST /api/transfers/<no>/receiveConfirm receipt. Returns 409 if already received or the wrong plant.
GET /api/job-orders/<no>/sfg-statusWhat the job order system needs: required, sent, in transit, received, missing per SFG.
GET /api/events?after_id=NThe trail as a feed. A consumer stores the last id it read, so nothing is missed or read twice.
GET /api/trail/verifyRecomputes the hash chain.
GET /export/sap-goods-movements.csvEvery send and receipt as an SAP-style goods movement line.

Field mapping to SAP

TrackerSAP
plant_code (1100, 1200, 1300)Plant (WERKS)
material_noMaterial (MATNR), type HALB for semi-finished
batchBatch (CHARG)
uomBase unit (MEINS)
SendMovement type 303: out of the issuing plant, booked as stock in transfer at the receiving plant
ReceiveMovement type 305: from stock in transfer into unrestricted stock at the receiving plant
Short quantityStays in stock in transfer until the rest is posted or the SAP team corrects it
transfer_noReference document (REF_DOC_NO)
job_order_noProduction order, once job orders live in SAP

This assumes SAP's two-step plant-to-plant transfer (303 then 305); a one-step transfer (301) also exists. If Indus moves stock with stock transport orders, the postings become 351 (or 641) then 101 against the order number, so the tracker would also store that number. Storage location is blank in the export for the SAP team to supply. All of this is to confirm with Indus's SAP team.
